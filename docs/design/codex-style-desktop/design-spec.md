# Vesta 对标 Codex 桌面端 UI/UX 设计规范 (Design Spec)

> 版本：v1.0  
> 日期：2026-11-16  
> 适用技术栈：Electron + React + TypeScript + CSS Custom Properties  
> 设计审查依据：`apple-design` skill 及 Apple Human Interface Guidelines (2025/2026)

---

## 1. 设计哲学与核心定位

### 1.1 设计宗旨：安静、专业、可掌控的 Agent 工作台
Vesta 桌面客户端对标 **OpenAI Codex 桌面应用**（`openai-codex-electron`），打造一款专注于工程任务与系统交互的 macOS 桌面级智能工作台。
我们拒绝当前 AI 界面中泛滥的“渐变流光、霓虹发光色、巨大装饰性数字与卡片堆叠”的模板化视觉，秉持 Apple 设计准则：
- **Clarity（清晰）**：以文本、排版间距与对齐传达层级，信息表达精准，不依赖繁复的视觉边框。
- **Deference（遵从）**：界面向用户内容与 Agent 执行成果退让，操作层保持轻量，让用户注意力完全集中在“正在完成的工作”上。
- **Depth（层次）**：通过严密的背景表面层级（Surface Hierarchy）与渐进式披露（Progressive Disclosure），将复杂的推理链路与工具调用按需组织，避免构建令人生畏的“监控仪表盘”。

### 1.2 Apple 2026 八大设计原则落地
依据 Apple HIG `design-principles.md`：
1. **Purpose（目的）**：界面的每一个像素均服务于“接收意图 → 执行推理 → 透明审批 → 交付产出”的核心链路。
2. **Agency（自主掌控）**：用户始终拥有最高控制权（Keep people in control）。清晰可达的“中断 / 停止 / 恢复”操作与防误触审批浮窗。
3. **Responsibility（负责透明）**：所有状态均来自后端真实事件流，杜绝伪造的假进度百分比；破坏性系统操作必须经过显式审批。
4. **Familiarity（平台熟悉度）**：严格贴合 macOS 窗口管理、系统菜单栏（Menu Bar）、标准快捷键（Cmd+N / Cmd+, / Cmd+W）与系统外观调度。
5. **Flexibility（弹性适应）**：支持 800×600 紧凑视窗至 4K 大屏自适应，正文排版具备 200% 文字缩放（Dynamic Type）承受能力。
6. **Simplicity（极简克制）**：剥离多余的状态指示器与次级标签，一律“通过间距与分组表达关系”。
7. **Craft（精工细作）**：字距、行高、焦点光圈（Focus Ring）、中文输入法组合（IME）等细节全面打磨。
8. **Delight（人性化愉悦）**：动效克制且仅用于状态转场，不做无意义的视觉装饰。

## 2. 精确 CSS 语义 Token 定义 (Semantic Tokens)

遵循 HIG `color.md`（“Avoid hard-coding system color values”）及 `cross-platform.md` 的跨平台 Web 翻译，所有颜色通过 CSS Custom Properties 统一管理，并严格匹配 macOS 浅色（Light）与深色（Dark）外观规范，附带 `@media (prefers-contrast: more)` 增强对比度支持。

### 2.1 语义色彩对照表与无障碍对比度（WCAG AA）

所有前景/背景对比度均经过真实 Hex 取样及公式计算，确保在默认模式下正文文本 ≥ 4.5:1，大字/次级文本 ≥ 3:1。

> [!IMPORTANT]
> **关于系统语义色与硬编码规则**：
> 依据 HIG `color.md`，上述取样 Hex 为设计评审与 Electron 渲染环境的基准测量值。在代码实现中，必须封装为 CSS 变量，并随 Electron `nativeTheme.shouldUseDarkColors` 与媒体查询进行统一联动。

### 2.2 增强对比度模式 (`prefers-contrast: more`)
当系统开启“增加对比度”（Increase Contrast）时：
- `--border-separator` 不透明度提升至 100%（浅色使用 `#B0B0B5`，深色使用 `#545458`）。
- `--text-secondary` 提升至一级对比（浅色 `#3A3A3C` 对比度 9.2:1，深色 `#D1D1D6` 对比度 9.8:1）。
- 所有交互式按钮和卡片增加 1.5px 实体边框，强化边界识别。

## 3. 排版标尺与字体系统 (Typography System)

依据 HIG `typography.md`（macOS 桌面标准），针对 1 到 3 英尺的桌面视距设定严密字阶。

### 3.1 字体栈定义 (Font Stacks)
- **系统主排版字体栈**（优先调用 Apple San Francisco 及其动态光学字形，并以苹方作为中文优先回退）：
  ```css
  font-family: -apple-system, BlinkMacSystemFont, "SF Pro Text", "SF Pro Display",
               "PingFang SC", "Hiragino Sans GB", "Helvetica Neue", sans-serif;
  ```
- **等宽代码与诊断字体栈**（优先调用 SF Mono，保证行号与代码对齐）：
  ```css
  font-family: "SF Mono", Monaco, Menlo, Consolas, "PingFang SC", monospace;
  ```

### 3.2 字阶标尺与层级定义

| 字阶层级 (Role) | 字号 (pt / px) | 字重 (Weight) | 行高 (Line Height) | 用途与场景 |
|---|---|---|---|---|
| **Title 1 / Window Header** | 16pt (16px) | Medium (500) / Semibold (600) | 22pt (1.38) | 窗口主标题、页面顶级模块标题 |
| **Headline / Section Header** | 14pt (14px) | Semibold (600) | 20pt (1.43) | 检查器分组标题、工具调用卡片标题 |
| **Body (正文主阅读区)** | **15pt (15px)** | Regular (400) | **24pt (1.60)** | **Assistant 与 User 对话正文、Markdown 长文本**（保障舒适长程阅读） |
| **UI Control / List (交互与列表)**| **13pt (13px)** | Regular (400) / Medium (500) | **18pt (1.38)** | **侧边栏会话列表项、按钮、输入框、下拉菜单、工具栏项** |
| **Footnote / Caption (辅助标签)** | 12pt (12px) | Regular (400) / Medium (500) | 16pt (1.33) | 时间戳、Token 用量说明、折叠提示文字、微型徽标 |
| **Code Block / Terminal** | **13pt (13px)** 起 | Regular (400) | **20pt (1.54)** | 源代码块、Shiki 高亮区域、参数 JSON 预览 |
| **Inline Code (行内代码)** | 12.5pt | Regular (400) | 保持行内 | Markdown 段落内的行内代码标记 |

### 3.3 字重规则与无障碍缩放要求
- **严禁使用细字重**：严格遵循 HIG `typography.md` 规则：“In general, avoid light font weights.” 禁止在任何 UI 与正文中采用 `Ultralight`、`Thin`、`Light` 字重，确保在低背光或弱视条件下的可辨识度。
- **支持 200% 文字缩放**：布局必须使用弹性单位（`rem` 基准或弹性 `flex/grid`），正文容器严禁设定写死的绝对高度，确保在系统文字放大 200% 时，卡片高度自适应扩展，绝无文本重叠或被剪切现象。

## 4. 工作区三栏布局与响应式断点 (Split View & Layout)

依据 HIG `split-views.md`、`sidebars.md`、`windows.md`，工作区采用清晰的**三栏弹性布局**，围绕“当前正在进行的工作”展开。

```text
┌────────────────────────────────────────────────────────────────────────────────────────┐
│ [● ● ●]  [Sidebar Toggle]  当前会话标题               [● Running / Idle]  [Stop] [Inspector ⊞] │ ← 统一工具栏 (44pt)
├───────────────────┬─────────────────────────────────────────────────┬──────────────────┤
│ 导航与近期会话     │ 主对话与工作流正文 (Center Pane)                 │ 可选检查器        │
│ (Leading Sidebar) │ (限制最大舒适阅读宽度 720-760pt)                 │ (Trailing)       │
│                   │                                                 │                  │
│ [＋ 新建工作区]   │  User: 重构数据加载模块                          │ ■ 当前任务 (Task) │
│                   │                                                 │   步骤 2/4       │
│ ▼ 近期会话        │  Assistant: 已分析现有链路，开始实施...          │                  │
│   ● 数据重构项目  │  ┌─ 思考过程 (折叠态，耗时 3.2s) ─────────────┐ │ ■ 工具调用历史   │
│     登录流程修复  │  └────────────────────────────────────────────┘ │   fs.read_file   │
│     API 接口校验  │  ┌─ 步骤任务面板 (3 步已完成 / 1 步待审批) ───┐ │                  │
│                   │  └────────────────────────────────────────────┘ │ ■ 生成交付物     │
│ ▼ 系统入口        │  正文输出与代码高亮块...                        │   - schema.ts    │
│   记忆 (Memory)   │                                                 │   - test.log     │
│   定时 (Auto)     │                                                 │                  │
│   全局活动 (Runs) │ ─────────────────────────────────────────────── │ [查看完整 Trace] │
│                   │ [Composer 输入区：输入意图...      (Normal/Plan) [↑]│                  │
└───────────────────┴─────────────────────────────────────────────────┴──────────────────┘
```

### 4.1 各分栏尺寸与行为规范

1. **左侧导航与会话侧栏 (Leading Sidebar)**：
   - **尺寸**：宽度范围 `220pt - 280pt`，默认 `240pt`。
   - **层级**：最多支持两层折叠（一级功能入口 + 二级会话列表），杜绝三层以上迷宫嵌套。
   - **控制**：可通过工具栏左侧按钮或快捷键 `Cmd+Option+S` 展开/隐藏；隐藏时主内容区平滑展开。
   - **安全底线**：严禁在侧栏底部放置关键审批或不可替代的破坏性按钮（符合 `sidebars.md` 规则）。

2. **主对话与工作区正文 (Center Workspace Pane)**：
   - **核心职责**：承载会话消息流、思考过程折叠、任务规划卡片、工具调用交互以及底部一体化 Composer。
   - **阅读流优化**：为防止大屏下文字单行过长导致视线跳动，对话正文设置最大阅读限制宽度：`max-width: 760pt`，并在 Pane 内水平居中。
   - **滚动机制**：独立垂直滚动，滚动条采用 macOS 悬浮滚动条模式（`overlay`）。

3. **右侧可选检查器 (Trailing Inspector Pane)**：
   - **尺寸**：宽度范围 `280pt - 360pt`，默认 `320pt`。
   - **核心职责**：展示与当前活跃 Run / Task 强相关的辅助细节：任务多阶段步骤（Current Task & Steps）、工具调用耗时与入参、生成的 Artifacts 交付物列表、以及进入诊断 Trace 的快捷入口。
   - **控制**：由工具栏右侧检查器图标或快捷键 `Cmd+Option+I` 控制显隐。

### 4.2 响应式断点与 800×600 降级策略

macOS 窗口必须支持自由缩放，设计基线目标涵盖 `800×600`（最小尺寸）、`1024×768`、`1200×800`（标准建议）及全屏。

| 窗口宽度断点 (Breakpoint) | 布局表现与自适应策略 | 保证与安全红线 |
|---|---|---|
| **≥ 1200pt (宽布局)** | 完整三栏同屏呈现（Sidebar 240pt + 主正文弹性展开 + Inspector 320pt）。 | 正文可用宽度 ≥ 640pt，阅读极度开阔。 |
| **960pt - 1199pt (中屏)** | **自动收起右侧 Inspector**，工具栏保持检查器切换按钮。需要查看详情时，Inspector 以右侧覆盖抽屉（Overlay Drawer）或弹出层（Popover）展示。 | 侧边栏与主正文稳定保持，主正文宽度充裕。 |
| **800pt - 959pt (紧凑布局)** | **进一步自动收起左侧 Sidebar** 为隐藏态，仅保留顶部工具栏最左侧的汉堡/展开图标（点击以浮动面板展开）。主正文独占视窗。 | **硬性约束：中心正文可用宽度不得低于 480pt**。杜绝水平滚动条。 |
| **高度 600pt - 720pt (紧凑高度)**| Composer 输入区自适应收紧内边距，最大撑高限制降为 140pt，预留至少 400pt 正文阅读空间。 | 底部输入框绝不遮挡最后一条消息的底部操作区。 |

### 4.3 统一窗口顶栏与交通灯规范 (Titlebar & Toolbar)
- **原生交通灯保护**：左上角 `[关闭 / 最小化 / 全屏]` 区域严格预留 `width: 78pt; height: 100%` 的安全间距，严禁任何自定义按钮重叠或遮挡。
- **拖拽区隔离**：顶栏背景统一配置 `-webkit-app-region: drag`，顶栏中的所有按钮、搜索框、状态胶囊必须显式标注 `-webkit-app-region: no-drag`，保证窗口可拖动性与控件可点击性完全解耦。

## 5. 核心交互组件详细设计规范

### 5.1 Composer 输入区 (一体化集成控制台)

位于主正文区底部，是整个应用发起意图的核心。

```text
┌────────────────────────────────────────────────────────────────────────┐
│ 意图描述输入区域... (支持 Markdown 粘贴与中文拼音组合输入)            │
│ (高度自适应: 最小 44pt，最大 200pt 后内部自然滚动)                      │
├────────────────────────────────────────────────────────────────────────┤
│ [ Normal / Plan 模式切换 ]        (草稿已保存)            [↑ 发送 ⏎]   │
└────────────────────────────────────────────────────────────────────────┘
```

1. **输入与 IME 行为规范**：
   - 采用原生强化 textarea，监听 `compositionstart` 与 `compositionend`。
   - 当 `isComposing === true`（拼音/候选词选词中）时，拦截 `Enter` 键事件，仅完成输入法候选词确认，**绝对禁止发送消息**。
   - 普通状态下：`Enter` 直接发送消息；`Shift + Enter` 插入换行符。提供应用菜单与上下文菜单的明确“发送”指令（支持 `Cmd + Enter` 作为备选发送）。
2. **高度自适应机制**：
   - 随文本输入平滑撑高（单行高度 44pt，随行数增加至最大 200pt），超过 200pt 后变为内部平滑滚动，不破坏窗口总体阅读流。
3. **模式切换胶囊 (Mode Capsule)**：
   - 提供 `Normal`（直接执行并对话）与 `Plan`（先规划多阶段步骤待审批后再执行）的双模切换开关，采用 macOS 分段控件（Segmented Control）风格。
4. **草稿隔离与持久性**：
   - 在客户端本次会话切换时，各会话的未发送草稿通过内存 store 隔离保留，切回原会话时完整复原光标与文字，避免用户输入意外丢失。
5. **防重入发送保护**：
   - 消息处于提交与等待首个 Token 阶段，发送按钮呈现禁用态或转为“停止 [■]”按钮，杜绝连击重复创建 Run。

### 5.2 流式 Agent 正文 (Streaming Message)

1. **流式渲染与节流刷新**：
   - 引入 33ms–50ms 的增量缓冲（Buffer Flush）机制，避免单个 Token 到达立即触发 React 重全量解析树与 Shiki 语法高亮重计算。
   - 渲染引擎容忍未闭合代码块（``` 未完结）、未闭合表格与截断链接，确保流式打字效果丝滑无闪烁。
2. **纯净复制能力**：
   - 代码块右上角提供一键复制按钮（Copy Button）。
   - 复制出的文本必须为纯净源代码，严格过滤行号、语言标签及 UI 图标。
3. **滚动锚定与“回到最新”悬浮指示器**：
   - 默认模式：当用户视口处于距离底部 80px 范围内时，新 Token 到达自动平滑跟随滚动。
   - 脱离模式：一旦用户向上滚动查看历史，立即解除自动滚动锁定（绝不强行抢占滚动）；同时在底部中央偏上浮现药丸型指示器：`[ 8条新消息 ↓ 回到最新 ]`，点击后平滑滚动回底部并恢复自动锁定。

### 5.3 思考过程折叠块 (Thinking / Reasoning Block)

遵循 HIG `layout.md` 之“Progressive disclosure”规则，不让内部思考淹没正式回复。

```text
┌────────────────────────────────────────────────────────────────────────┐
│ ✦ 正在深度思考规划... (微脉冲波纹动画)                        [展开详情 ▼] │
├────────────────────────────────────────────────────────────────────────┤
│ (展开后：等宽 12pt 文字，背景 --surface-grouped，展示 Chain-of-thought)│
└────────────────────────────────────────────────────────────────────────┘
```
- **生成期间**：呈现轻量收拢卡片，显示微妙的脉冲指示器与“正在思考...”状态。
- **完成状态**：自动收拢为单行胶囊：“已深度思考 4.2 秒 [展开 ▼]”。
- **展开体验**：点击三角或标题行平滑展开，内部采用 12pt 紧凑排版与 `--surface-grouped` 弱对比底色，与最终正式答复形成显著的视觉区分。

### 5.4 工具调用卡片 (Tool Call Card)

将底层黑盒工具调用具象化为清晰可读的操作卡片。

```text
┌────────────────────────────────────────────────────────────────────────┐
│ ⚙︎ fs.write_file  "src/utils/parser.ts"          [耗时 120ms]  [成功 ✓] │
├────────────────────────────────────────────────────────────────────────┤
│ [展开调用参数 JSON]                                                     │
│ > 变更摘要：更新 Token 解析正则匹配规则 (+12 行, -3 行)                  │
└────────────────────────────────────────────────────────────────────────┘
```
- **卡片头部**：清晰展示工具图标、工具名称、关键操作对象（如文件路径或命令名）、耗时以及状态图标（成功绿色对勾、错误红色感叹号）。
- **参数与输出渐进展开**：默认收起原始冗长的 JSON 参数与大段终端输出，仅展示关键动作摘要；点击卡片可展开语法高亮后的具体参数与输出。
- **错误高亮**：若工具调用报错，卡片边框转为弱警告红（`--status-error`），并在展开区提供清晰的报错信息与“重试/跳过”引导。

### 5.6 独立无焦点审批浮窗 (Approval Floating Window)

依据 HIG `panels.md` 与第 3.5 节“有意例外”约束：由于 Vesta 支持 Computer 操作（跨应用控制 macOS 屏幕与鼠标），用户在其他前台应用（如 Xcode、Chrome、Terminal）工作时，审批通知不能抢占当前输入焦点。

```text
┌────────────────────────────────────────────────────────────────────────┐
│ ⚠️ Vesta 系统权限审批请求                          (不抢占当前窗口焦点)│
├────────────────────────────────────────────────────────────────────────┤
│ 动作：bash.execute                                                     │
│ 命令：rm -rf ./dist && npm run build                                   │
│ 风险等级：中度风险 (文件清理与构建)                                    │
├────────────────────────────────────────────────────────────────────────┤
│ [ 前往主窗口查看详细上下文 ]             [ 拒绝 (Esc) ]  [ 批准并执行 (⏎) ]│
└────────────────────────────────────────────────────────────────────────┘
```
- **窗口属性规范**：
  - Electron 配置：`focusable: false`, `alwaysOnTop: true`, `showInactive()`, `acceptFirstMouse: true`。
  - 弹出位置：智能识别当前鼠标所在显示器的右上角或右下角工作区边界，避开系统菜单栏与 Dock 栏。
- **交互与焦点隔离**：
  - 点击浮窗内的“批准”或“拒绝”按钮时，由底层原生事件快速处理，**绝对不将系统键盘焦点从目标应用（如用户正在编码的 IDE）切走**。
  - 对于需要复杂输入或查看完整上下文的审批，提供“前往主窗口查看”按钮，此时才显式激活 Vesta 主窗口。
- **状态防重复与去重**：
  - 审批操作在主窗口与浮窗间通过 Electron IPC 统一收拢到集中审批控制器，操作一旦触发立即锁定，严禁多次重复提交。

## 6. 无障碍规范与交互细节 (Accessibility Checklist)

1. **控件点击与命中热区 (Hit Targets)**：
   - 遵循 HIG `accessibility.md`（macOS 规范）：普通可交互控件（图标按钮、列表行操作项）尺寸不低于 **28×28pt**；紧凑型工具栏微控件不低于 **20×20pt**，且控件间保留至少 12pt 的点击防误触间距。
2. **非颜色依赖的信息传达 (Inclusive Signals)**：
   - 每一个状态反馈必须同时具备“**形状 + 文本 + 颜色**”三重表征。例如运行成功不仅显示绿色，必须伴随 Checkmark 图标与“已完成”文字；运行失败伴随 Alert-triangle 图标与“失败”说明。
3. **全键盘可达性与焦点环 (Focus Rings)**：
   - 所有交互组件（按钮、输入框、折叠器、列表项）均可通过 `Tab` / `Shift+Tab` 遍历。
   - 处于获得焦点状态的元素呈现 macOS 标准的 2px 外发光焦点环（`box-shadow: 0 0 0 2px var(--border-focus)`）。
4. **减弱动态与减弱透明度适配**：
   - 监听 `@media (prefers-reduced-motion: reduce)`：禁用所有平滑滚动与展开动画，直接使用瞬时状态切换。
   - 监听 `@media (prefers-reduced-transparency: reduce)`：所有半透明与毛玻璃效果替换为实底纯色表面。
